## 0. この文書の位置づけと限界

**この文書は「実装から読み取れる現在の仕様」を整理したものであり、開発当初に定義された要求仕様書ではありません。**

サクラエディタは 1998 年に開発が始まり、多数の開発者が四半世紀にわたって育ててきた
オープンソースソフトウェアです。当初の要求定義書は存在せず、
個々の機能がなぜ追加されたのかという意思決定の記録も、
issue や PR に散在するのみで体系化されていません。

したがって本書は次の性質を持ちます。

| 記述できること | 記述できないこと |
|---|---|
| 現在どう動作するか（コードから確認可能） | なぜその仕様が選ばれたか（設計判断の記録が無い） |
| どんな制約が課されているか | 制約の優先順位、トレードオフの判断基準 |
| 何が実装されているか | 意図的な非目標（やらないと決めたこと） |

「なぜ」の部分は推測で埋めず、**空欄または「根拠不明」と明記**しています。
コード上の根拠が明確なものだけ、出典を添えて理由を記載しました。

この文書は「現状の追認」であって「あるべき姿の定義」ではありません。
新機能の妥当性判断に使う場合は、この点に注意してください。

## 1. プロダクト概要

### 1.1 目的

Microsoft Windows 上で動作する、日本語テキストの編集に適した汎用テキストエディタ。

### 1.2 位置づけ

| 属性 | 内容 |
|---|---|
| ライセンス | zlib License |
| 対象プラットフォーム | Windows（`_WIN32_WINNT=_WIN32_WINNT_WIN10` / `WINVER=0x0A00`） |
| 実装言語 | C++20 |
| 配布形態 | インストーラ版 / ZIP 版 |
| 課金 | 無償 |

### 1.3 想定利用者

コード上の根拠が無いため断定できませんが、実装されている機能から次が読み取れます。

- 日本語テキストを扱う一般利用者（多様な文字コード対応、Migemo 検索）
- プログラマ（シンタックスハイライト、タグジャンプ、Grep、マクロ、差分表示）
- 大きなログ・データファイルを扱う利用者（矩形選択。巨大ファイルは
  検証用スクリプト `tools/create-big-file.py` が用意されていることから、
  少なくとも動作確認の対象にはなっていると読み取れます）

## 2. 機能要求

機能はコマンド（`EFunctionCode`）として定義されます。
分類は `sakura_core/Funccode_x.hsrc` のカテゴリ区分に従います。
コマンド全一覧は [付録 A](#付録-a-機能コマンド一覧) を参照してください。

| ID | ドメイン | コマンド数 | 主な内容 |
|---|---|---|---|
| FR-01 | ファイル操作 | 38 | 新規・開く・保存・閉じる・印刷・最近使ったファイル |
| FR-02 | 編集 | 19 | 挿入・削除・Undo/Redo・インデント |
| FR-03 | カーソル移動 | 33 | 文字/単語/行/画面/ファイル単位の移動 |
| FR-04 | 選択 | 20 | 範囲選択（移動系と対になる） |
| FR-05 | 矩形選択 | 14 | 矩形（ボックス）選択 |
| FR-06 | クリップボード | 18 | 切り取り・コピー・貼り付け（矩形/ラインモード含む） |
| FR-07 | 挿入 | 6 | 日付・時刻・ファイル取り込み |
| FR-08 | 変換 | 25 | 大小文字・全角半角・文字コード・タブ空白変換 |
| FR-09 | 検索 | 46 | 検索・置換・Grep・インクリメンタルサーチ・ブックマーク |
| FR-10 | モード切り替え | 9 | 挿入/上書き、ビューモード、フリーカーソル |
| FR-11 | 設定 | 42 | 共通設定・タイプ別設定・フォント・折り返し |
| FR-12 | マクロ | 7 | キーマクロの記録・実行・保存 |
| FR-13 | ウィンドウ | 33 | 分割・タブ・整列・最小化 |
| FR-14 | 支援 | 9 | ヘルプ・外部ツール連携 |
| FR-15 | カスタムメニュー | 26 | 利用者定義メニュー |

### 2.1 FR-01 ファイル操作

**要求**: 利用者はテキストファイルを開き、編集し、保存できること。

| 項目 | 仕様 |
|---|---|
| 文字コード | 自動判別および明示指定で開ける（[3.1](#31-対応文字コード) 参照） |
| 改行コード | CRLF / LF / CR / NEL / LS / PS を認識し、混在も扱える |
| 排他制御 | `CDocLocker` により編集中ファイルの排他状態を管理 |
| 外部更新検出 | `CAutoReloadAgent` が外部変更を検出し再読み込みできる |
| バックアップ | `CBackupAgent` が保存時にバックアップを生成できる |
| 自動保存 | `CAutoSaveAgent` が定期的に保存できる |

**未確定**: 扱えるファイルサイズの上限は定数として定義されておらず、
実質的にはメモリと `CDocLineMgr` の実装に依存します。明示的な要求値は不明です。

### 2.2 FR-09 検索

サクラエディタで最もコマンド数が多いドメインです（46 個）。

| 機能 | 実装 |
|---|---|
| 通常検索・置換 | `CSearchAgent` |
| 正規表現検索 | 外部ライブラリ（Onigmo / bregonig）に委譲 |
| Migemo 検索 | ローマ字入力で日本語を検索。cmigemo に委譲 |
| Grep | 複数ファイル横断検索。`CGrepAgent` + `grep/` のファイル走査 |
| Grep 置換 | 複数ファイル横断置換 |
| インクリメンタルサーチ | `CEditView_Cmdisrch.cpp` |
| ブックマーク | 行への印付けと移動 |
| タグジャンプ | ctags 連携（`extmodule/`） |

### 2.3 FR-12 マクロ / 拡張性

**要求**: 利用者が処理を自動化でき、第三者が機能を追加できること。

| 拡張手段 | 形式 |
|---|---|
| キーマクロ | 操作の記録・再生 |
| PPA マクロ | 独自スクリプト言語 |
| WSH マクロ | JScript / VBScript |
| Python マクロ | Python |
| DLL プラグイン | Win32 DLL |
| WSH プラグイン | スクリプト |

プラグインの拡張点（ジャック）は 10 種類定義されています。
詳細は [コンポーネント設計書](component-design.md) を参照してください。

## 3. 制約

制約はコードから確認できるため、本書で最も確度が高い部分です。

### 3.1 対応文字コード

`sakura_core/charset/charset.h` の `ECodeType` が定義です。

| 種別 | 備考 |
|---|---|
| Shift_JIS | MS-CP932 (Windows-31J) |
| JIS | MS-CP5022x (ISO-2022-JP-MS) **ではない** |
| EUC | MS-CP51932。eucJP-ms (eucJP-open) **ではない** |
| UTF-16 LE / BE | |
| UTF-8 | |
| UTF-7 | |
| CESU-8 | |
| Latin1 | Windows-1252 |
| UTF-32 LE / BE | |
| ANSI コードページ / OEM コードページ | 実行環境依存 |

**内部表現は UTF-16 に統一**され、入出力の境界でのみ変換します。
自動判別は `CCodeMediator` / `CESI` が担当します。

> JIS と EUC について「MS-CP5022x ではない」「eucJP-ms ではない」と
> ヘッダにわざわざ明記されている点は、互換性上の意図的な選択と読み取れます。
> ただし判断の経緯を示す記録はコード上にありません。

### 3.2 対応改行コード

`sakura_core/basis/CEol.h` の `EEolType`。

| 値 | コード |
|---|---|
| `cr_and_lf` | `\x0D\x0A` |
| `line_feed` | `\x0A` |
| `carriage_return` | `\x0D` |
| `next_line` | `\u0085` (NEL) |
| `line_separator` | `\u2028` (LS) |
| `paragraph_separator` | `\u2029` (PS) |

### 3.3 数量上限

`sakura_core/env/CommonSetting.h` ほかで定義される固定上限です。

| 対象 | 上限 | 定数 |
|---|---|---|
| 分割ペイン数 | 4 | `CEditViewsArray` の要素数 |
| ツールバーボタン登録数 | 512 | `MAX_TOOLBAR_BUTTON_ITEMS` |
| ツールバーアイコン数 | 480 (32×15) | `MAX_TOOLBAR_ICON_COUNT` |
| カスタムメニュー数 | 25 | `MAX_CUSTOM_MENU` |
| カスタムメニュー項目数 | 48 | `MAX_CUSTOM_MENU_ITEMS` |
| ウィンドウキャプション長 | 256 | `MAX_CAPTION_CONF_LEN` |
| 日付書式長 | 100 | `MAX_DATETIMEFOREMAT_LEN` |

### 3.4 機能コード体系の制約

`Funccode_x.hsrc` 冒頭に記載された制約です。

| 範囲 | 用途 |
|---|---|
| 10000〜 | ウィンドウ一覧 |
| 11000〜 | 最近使ったファイル |
| 12000〜 | 最近使ったフォルダー |
| 20000〜21999 | プラグインコマンド（20 個 × 100） |
| 30000〜32767 | メニュー・キーに割り当て可能な機能 |
| 32768〜39999 | メニューから直接呼ばれず、他 ID から間接的に呼ばれる機能 |
| 40000〜49511 | マクロ関数 |
| 49512〜 | 変換コマンド（状況に応じて機能を置き換える） |

**`30000〜32767` という上限には歴史的な理由が明記されています。**

> Windows 95 では 32768 以上のコマンドをメニューやアクセラレータに設定すると動作しない。
> — `Funccode_x.hsrc`

これは現在サポート対象外の OS に由来する制約が、
コード体系として残っている例です。互換性維持のため変更されていません。

### 3.5 プラットフォーム制約

- Windows 専用。UI 層が Win32 API と GDI に強く結合しており、
  移植性は考慮されていません（[アーキテクチャ設計書](architecture.md) 参照）
- 二プロセスモデルは共有メモリ（`CreateFileMapping` / `MapViewOfFile`）に依存
- プラグイン機構は Win32 DLL ABI に依存

### 3.6 開発・ビルド上の制約

| 制約 | 内容 |
|---|---|
| ソース文字コード | `.cpp` / `.h` は UTF-8 BOM 付きまたは ASCII、`.rc` / `.rc2` は UTF-16。CI が検査 |
| 主ビルド系 | MSVC（`sakura.sln`）。MinGW/CMake は実験的 |
| ソース追加 | `sakura_core/sakura.vcxproj` への明示的な追記が必要 |
| 共有データ変更 | `N_SHAREDATA_VERSION` の更新が必須 |
| リソース変更 | 日本語・en-US・zh-CN の 3 言語すべてを揃える必要がある |

## 4. 品質要求

明文化された数値目標はコード上に存在しません。
以下は**実装から読み取れる、重視されていると推測される品質特性**です。
根拠となるコード上の痕跡を併記します。

| ID | 品質特性 | 読み取れる方針 | コード上の根拠 |
|---|---|---|---|
| QR-01 | 後方互換性 | 極めて重視。旧 OS 由来の制約すら維持 | `Funccode_x.hsrc` の Windows 95 制約、設定の既定値維持 |
| QR-02 | 表示性能 | 重視。描画のキャッシュと計算量削減の工夫が多い | `m_bUseCompatibleBMP`（再作画用互換ビットマップ）、`SCharWidthCache`（文字幅キャッシュ） |
| QR-03 | 起動速度 | 意識されている | `CRunningTimer` による計測コードが各所に埋め込まれている。イメージリスト構築の最適化コメント（「250msecくらい速度が改善される」） |
| QR-04 | 多重起動時の一貫性 | 重視 | 二プロセスモデルと `DLLSHAREDATA` による設定の一元管理 |
| QR-05 | 正確性（型安全） | 部分的に重視 | `CStrictInteger` による論理行/レイアウト行の型分離。ただし MSVC Debug ビルド限定 |
| QR-06 | 国際化 | 限定的 | 日本語が基準。en-US / zh-CN のリソース DLL のみ |
| QR-07 | 拡張性 | 重視 | マクロ 4 種、プラグイン 2 種、ジャック 10 種 |

**未確定**: 応答時間、メモリ使用量、扱えるファイルサイズについて、
数値目標を示す記述はコード上に見当たりません。
