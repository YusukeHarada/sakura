# サクラエディタ 設計ドキュメント

サクラエディタの構造を説明する文書群です。3 層で構成しています。

| 文書 | 扱う範囲 | こんなときに読む |
|---|---|---|
| [要求仕様書](requirements.md) | 何ができるか、どんな制約があるか | 対応文字コードや上限値を知りたい。機能の全体像を掴みたい |
| [アーキテクチャ設計書](architecture.md) | サブシステム**間**の構造と設計判断 | 全体の地図が欲しい。なぜこの構造なのかを知りたい |
| [コンポーネント設計書](component-design.md) | 各サブシステムの**内部** | 特定の箇所に手を入れる。拡張点を探している |

```
要求仕様書        「何を」 ─── 制約・品質要求
     ↓
アーキテクチャ設計書 「どう分けたか」 ─── サブシステム間の構造、設計判断と根拠
     ↓
コンポーネント設計書 「中身はどうなっているか」 ─── データ構造、拡張手順
```

## この文書群の性質

**いずれも実装から読み取って書かれた as-built 文書です。**
サクラエディタには開発当初の要求定義書もアーキテクチャ設計書も存在しません。

そのため各文書では次の方針を取っています。

- コードから確認できる事実と、実装からの推定を**区別して明記**する
- 「なぜそうなったか」の記録が無いものは推測で埋めず、**不明と書く**
- 判断が必要な未確定事項は各文書の末尾に列挙する
  （[要求仕様書 付録 B](requirements.md#付録-b-未確定事項)）

現状の追認であって「あるべき姿」の定義ではない点に注意してください。
